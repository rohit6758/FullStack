Concepts of Web Hosting, Domain Names, and the Role of DNS

Course Outcome: CO1 / CO5 | Bloom's Level: L2 (Understand) | 5 Marks

1 Concept of Web Hosting

Web hosting is an infrastructure service that allocates physical or virtual server computing resources (CPU, RAM, persistent storage, and high-speed network bandwidth) connected to the internet 24/7/365. It runs the web server daemons, runtimes, and databases required to serve web applications to global users.

In our Student Management System, hosting is decoupled into specialized tiers:

  • Frontend Web Hosting (Vercel): Distributes compiled static React Single Page Application (SPA) files across a Global Edge Content Delivery Network (CDN) for low-latency delivery.
  • Backend API Hosting (Render): Runs the dynamic Node.js/Express.js service inside a managed Linux container with persistent socket listeners and automatic routing.
  • Database Hosting (MongoDB Atlas): Provides managed cloud Database-as-a-Service (DBaaS) with 3-node replica sets for automated failover and data redundancy.

2 Concept of Domain Names

A Domain Name is a human-readable alphanumeric identifier (such as sms-frontend.vercel.app) that abstracts machine-level numerical IP addresses (such as 76.76.21.21). Domain names follow a structured hierarchical tree:

  • Top-Level Domain (TLD): The highest level in the DNS tree (e.g., .app, .com, .edu).
  • Second-Level Domain (SLD): The unique project/organization brand (e.g., vercel in vercel.app).
  • Subdomain: Designates a specific application or service (e.g., sms-frontend).

3 Role of DNS in Making a Deployed Application Accessible

The Domain Name System (DNS) functions as the distributed "phonebook of the Internet." When a user inputs a URL into their browser, DNS translates the human-friendly domain into a routable IP address through an iterative resolution chain:

  1. Cache Inspection: Browser checks internal memory cache and OS resolver cache for the domain.
  2. Recursive Resolver: If not cached, the ISP's Recursive Resolver receives the query.
  3. Root Nameserver (.): Directs the resolver to the responsible TLD nameserver.
  4. TLD Nameserver (.app): Directs the resolver to the Authoritative Nameserver (e.g. Vercel DNS).
  5. Authoritative Nameserver: Delivers the definitive A Record (IP address) or CNAME Record with a Time-To-Live (TTL).
  6. Connection Handshake: The browser initiates a TCP handshake on port 443, completes TLS encryption, and retrieves the React web application bundle.
